# UserRepo — описание тестирования

## 1. Цель тестирования

Проверить корректность взаимодействия класса `UserRepo` с базой данных SQLite: сохранение пользователей, получение записей, проверку существования и удаление пользователей.

Также проверяется восстановление объектов `User` из данных, полученных из базы данных.

## 2. Проверяемые методы

### `save_user(user)`

Проверяется:

* сохранение пользователя в таблицу `users`;
* корректное сохранение идентификатора, имени пользователя, роли и даты создания;
* отклонение повторного сохранения пользователя с уже существующим `username`;
* возникновение `UserAlreadyExistsError` при обнаружении дубликата.

### `get_user_by_username(username)`

Проверяется:

* получение пользователя по имени;
* восстановление объекта `User` из записи SQLite;
* корректное восстановление UUID, роли и даты создания;
* возврат `None`, если пользователь не найден.

### `get_user_by_id(user_id)`

Проверяется:

* получение пользователя по UUID;
* корректное восстановление объекта `User`;
* возврат `None`, если пользователь с указанным UUID отсутствует.

### `get_all_users()`

Проверяется:

* получение всех пользователей из таблицы;
* преобразование полученных записей в объекты `User`;
* формирование списка объектов пользователей.

### `exists_by_username(username)`

Проверяется:

* возврат `True`, если пользователь с указанным именем существует;
* возврат `False`, если пользователь отсутствует.

### `exists_by_id(user_id)`

Проверяется:

* возврат `True`, если пользователь с указанным UUID существует;
* возврат `False`, если пользователь отсутствует.

### `delete_user_by_id(user_id)`

Проверяется:

* удаление пользователя по UUID;
* отсутствие пользователя в базе данных после удаления.

### `delete_user_by_username(username)`

Проверяется:

* удаление пользователя по имени;
* отсутствие пользователя в базе данных после удаления.

## 3. Организация тестирования

* Для тестирования используется `pytest`.
* Для каждого теста создаётся отдельная временная база данных SQLite.
* Таблица `users` создаётся с ограничениями `PRIMARY KEY` для `id` и `UNIQUE` для `username`.
* После завершения тестов временные файлы базы данных очищаются механизмом `tmp_path` от pytest.
* Проверяется взаимодействие репозитория с реальной SQLite, а не только вызовы методов с помощью моков.

## 4. Результат

Все тесты файла `tests/repository/test_user_repo.py` пройдены.

Это подтверждает корректность проверенных сценариев работы `UserRepo` в условиях тестирования.

## 5. Ограничения текущего тестирования

Успешное прохождение тестов не гарантирует отсутствие всех возможных ошибок. В частности, отдельно могут потребоваться проверки:

* пустой таблицы при вызове `get_all_users()`;
* конфликтов UUID и `username` по отдельности;
* некорректных аргументов методов;
* ошибок SQLite и поведения при сбоях транзакций;
* конкурентного доступа к базе данных из нескольких потоков.
